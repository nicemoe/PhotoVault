# 查重

一堆小说 txt 里把重复的挑出来。纯 Win32，编出来是一个 246 KB 的独立 exe，
零依赖（MD5 用系统的 bcrypt）。

## 为什么不能只比 MD5

同一本书往往存了好几份，但字节层面各不相同：

- 文件名不一样：`《斗破苍穹》.txt` / `斗破苍穹(全本).txt` / `斗破苍穹【精校】.txt`
- 编码不一样：UTF-8、GBK、UTF-16
- 排版不一样：换行符、段首缩进、行尾空格
- 有一份是下到一半的
- 有一份正文里夹了广告页

MD5 只抓得住第一种情况之外什么都不是的那一种。所以从严到松叠了五层判据。

## 五层判据

| 依据 | 抓的是什么 | 怎么做的 |
|---|---|---|
| **完全相同** | 字节一模一样 | 原始 MD5 |
| **正文相同（编码或排版不同）** | 同一本书，只是存的编码或排版不同 | 解码 → 去掉所有空白 → MD5 |
| **开头相同** | 一份是另一份的截断版 | 归一化正文前 5000 字的 MD5 |
| **正文相似 xx%** | 多了广告页、少了几章 | 四字片段 MinHash |
| **书名相似 xx%** | 去掉修饰后书名一致，正文未必相同 | 书名字符二元组 Jaccard |

前三层是「完全相等」，用哈希表分桶，O(n)。后两层要两两比，但都是整数运算，
几千个文件也就几百万次，很快。

## 关于「分词」

中文没有空格，切词不靠词典——词典缺词就会漏判，而小说里生造的人名地名最多。
这里全部用**字符 N 元组**：

- **书名**用二元组算 Jaccard。「斗破苍穹」和「斗破苍穹后传」交集 3、并集 5，
  算出来 0.6，低于 0.85 的阈值，正好不会把续作当成同一本
- **正文**用**四字**片段。一开始正文也用二元组配 SimHash，测出来两本完全不同
  的小说指纹只差 1 位——中文散文的字频高度集中，常用字来回就那些，两本不相干
  的书在「二元组分布」这个维度上本来就长得几乎一样，而 SimHash 量的正是这个
  分布。换成四字片段就区分得开：不相干的两本书几乎不会有相同的四字串，
  同一本书的两份拷贝则共享绝大多数

正文相似度用 bottom-k MinHash（留最小的 128 个片段散列），出来直接是个百分比，
比「汉明距离 3 位以内」这种说法好判断得多。阈值在界面右上角可调，默认 80%。

## 文件名怎么归一化

```
《斗破苍穹》(全本)【精校】- 天蚕土豆.txt   →   斗破苍穹天蚕土豆
```

1. 去扩展名
2. 脱括号。`【】()（）[]` 连里面的内容一起丢——装的多半是「完结」「精校」这类
   修饰；`《》` 只脱壳、内容留着，因为书名正装在里面
3. 删噪声词：全本、完本、完结、精校、下载、免费、笔趣阁……
4. 抹掉分隔符和西文标点

**数字不删**：《三体2》和《三体3》是两本书。

## 用法

1. 把文件夹拖进窗口（也可以拖到 exe 图标上，或用「添加文件夹」）
2. 点「开始查重」
3. 看结果。**该删的默认已经勾上**，但「书名相似」这条证据弱，不会自动勾
4. 「移到 _重复」或「删到回收站」

留哪一份的规则：字数差超过 2% 就要字多的（少的那份多半没下完）；
字数接近就要名字干净的——夹了广告页的那份反而更长，而多出来的广告
往往也会在文件名里留下痕迹。

动手之前可以先点「导出清单」，在扫描根下生成 `_查重清单.txt`，
把分组和依据都写清楚，留个凭据。

`_重复` 目录在扫描时会跳过，挪出去的不会再被扫回来。
