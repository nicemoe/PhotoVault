# 转片

把手机放不了的视频批量转成 iOS 能直接播的 mp4。纯 Win32，编出来是一个
226 KB 的独立 exe，除了 ffmpeg 没有别的依赖。

## 为什么在电脑上转

iOS 只有 H.264 和 HEVC 有硬件解码器。mkv、rmvb、wmv 这些要么封装不认、
要么编码不认。在手机里塞一套软解码器（试过 KSPlayer + FFmpeg）能放，
但费电、发热、rmvb/wmv/avi 还会花屏。在电脑上转一次，之后每次播放都是
硬件解码——省电、拖进度条跟手、不发热。

## 用法

1. 把 `ffmpeg.exe` 和 `ffprobe.exe` 放到 `转片.exe` 旁边
   （<https://www.gyan.dev/ffmpeg/builds/> 下载 release essentials，
   解压后从 `bin` 里取这两个文件）
2. 双击 `转片.exe`
3. 把视频文件或整个文件夹**直接拖进窗口**，也可以用「添加文件 / 添加文件夹」；
   在资源管理器里选中一堆视频拖到 exe 图标上，或者右键「发送到」，也能一次全丢进来
4. 选好输出目录，点「开始」

之后就不用管了，它会一个一个转完，全部结束时闪一下任务栏。转换期间会
阻止电脑休眠（不挡息屏）。

## 两种处理方式

程序先用 ffprobe 看一眼文件里装的是什么，再决定怎么处理：

| 情况 | 处理 | 耗时 |
|---|---|---|
| 视频已经是 H.264/HEVC，音频是 AAC | **换壳** —— 只换 mp4 容器，不重新编码 | 几秒 |
| 视频合规、音频不合规 | 换壳 + 只转音频 | 十几秒 |
| 视频不合规（RealVideo、VC-1、MPEG-4 ASP…） | **重新编码** libx264 CRF 20 | 看片长和机器 |

很多 mkv 里装的本来就是 H.264，卡住 iOS 的只是那层容器——这种走「换壳」，
几秒钟搞定而且**画质零损失**。真正要重新编码的只有 rmvb 这类老编码。

## 和 App 的配合

按文件夹添加时会保留子目录结构，转出来的文件按同样的层级摆好。因为百宝箱
的「导入」文件夹正是按目录层级分组的：

```
导入/2025 京都/大阪/a.mp4   →  分组「2025 京都」→ 目录「大阪」
```

所以转完直接把输出目录整个拖进手机的「导入」文件夹，分组目录就自动建好了。

## 一些实现上的取舍

- **虚拟列表**（`LVS_OWNERDATA`）：几千个文件也不用往控件里塞几千份字符串
- **只映射第一路视频和第一路音频**（`-map 0:V:0 -map 0:a:0?`）：mkv 常带字幕流，
  mp4 装不下，不显式挑的话 ffmpeg 会直接报错退出。大写 `V` 还能跳过内嵌封面图
- **`-movflags +faststart`**：索引挪到文件开头，拖进度条不用先读到文件尾
- **「跳过已经转好的」默认开着**：中途关掉再开能接着来，不用重头跑
- **同名文件先写 `.tmp.mp4`**：源和目标撞名时不会把源文件截断

## 编译

```powershell
.\build.ps1
```

需要 MSVC + Windows SDK。脚本顶部写死了这台机器上便携版 MSVC 的路径，
换机器改一下，或者直接在「x64 Native Tools 命令提示符」里：

```
cl /nologo /utf-8 /O2 /MT /EHsc /std:c++17 /DUNICODE /D_UNICODE main.cpp /link /SUBSYSTEM:WINDOWS
```

`/MT` 是静态链接运行库，拷到没装 VC 运行库的机器上也能跑。
